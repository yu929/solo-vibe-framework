# 场景一 · 全新产品

> 从一句话想法到第一个能开工的纵向切片。

## 什么时候用这个场景

**判据（满足任一条）**：

- 还没有共识的产品结构——说不清有哪几块能力、先做哪一块
- 要做的是一整块新东西，不是在已有结构上加
- 你自己也还没完全想清楚要什么

**不用这个场景的情况**：

- 结构已定，只是加个新能力 → [`02-feat-dev.md`](02-feat-dev.md)
- 只改一条规则、修一个 bug → [`03-fix-bug.md`](03-fix-bug.md)
- 你已经想清楚了第一片做什么 → 直接进 Trellis，简报是可选的

## 开始之前

- [ ] 照 [`00-setup.md`](00-setup.md) 装完了
- [ ] 仓库已建，`trellis init` 跑过
- [ ] 你有一段能说出口的想法——**不需要想清楚**，那正是接下来要做的事

## 这一篇在补什么

**Trellis 有需求收敛，但只在 task 内部。** 它的 `trellis-brainstorm` 会一问一答帮你把这一个 task 想清楚，还有个硬门禁（没显式批准 planning summary 就不许开工）。那部分很好用，本手册不复述。

它没有的是**task 之上那一层**：

- 这个产品整体要去哪（`.trellis/spec/` 只放编码规范，`prd.md` 只记单次改动，journal 只是时间流水——跑五十个 task 也没有一处回答「这产品现在整体是什么」）
- 先做哪一片、后做哪一片（Trellis 明说父子任务树不是依赖系统）

所以这一篇只做两件事：**写一份产品简报**，然后**从它切出第一片**。之后交给 Trellis。

## 步骤

### 步骤 1 · 写产品简报

**我敲什么**：

```
我想做 <一段话，不用组织>。
用 playbook/assets/brief-template.md 的结构，帮我落成 docs/discovery/brief.md。
先把你能自己查的查了（现有仓库有什么、技术上有没有明显不可行的点），
剩下真需要我拍板的，一次列出来，每题给个推荐答案。
```

**AI 会产出什么**：一批编号问题（每题带推荐答案），你答完之后是 `docs/discovery/brief.md`，六节，一页。

装了 `grilling` 的话它会用 frontier 机制组织问题——前置已定的一次问完，依赖未决的排到下一轮。**环境事实它该自己查，不该问你。**

#### 收尾：把问出来的东西分三类

**这一步必须显式做，别指望它自动发生。** grilling 的停止条件是 frontier 空——无界的，一轮一轮问下去很正常。问出来的东西会远多于简报能装的，而**简报装不下不是简报太小，是它们本来就不该都进简报**：

| 问出来的 | 落哪 | 为什么 |
|---|---|---|
| **环境事实**（现有仓库有什么、某个库支不支持、这个格式解析得出来吗） | **哪也不落** | 它是 AI 该自己查的，查完用掉即可。存下来只会过期 |
| **需求边界**（做什么、不做什么、给谁用、什么时候算做完） | 简报 §2 §3 §6 | 这是简报的正题 |
| **有取舍的决定**（当时另一个选项也能走通，被否掉了） | `docs/discovery/decisions.md` | 简报答「做什么」，它答「为什么是这样」 |

分不清一条属于哪类时问：**它是"事实"、"范围"，还是"选择"？** 只有选择进决策记录。

决策记录用 [`assets/decisions-template.md`](assets/decisions-template.md)，**准入卡三条判据**：难以回退 + 没上下文会困惑 + 真有取舍，**三条全中才写**。不卡这三条它会在两周内变成对话转储，那时比不存在更糟——没人愿意读的档案等于没有档案。

**我敲什么**：

```
刚才问出来的，按三类分：
环境事实（丢掉）/ 需求边界（进 brief 哪一节）/ 有取舍的决定（进 decisions.md）。
第三类按 playbook/assets/decisions-template.md 的三条判据筛，
缺一条就不写，并告诉我它缺哪条。
```

最后一句是防它把什么都判成"有取舍"——**让它说出缺哪条判据，比让它自己把关有效**。

**六节里真正要紧的是两节**：

| 节 | 看什么 |
|---|---|
| **§2 当前阶段目标** | 是不是**一条端到端的用户价值**（「用户能配置并跑通一次同步」），不是一批功能（「做完三个模块」） |
| **§3 能力地图 · 明确不做** | 「不做」清单在不在、每条有没有原因 |

**怎么确认这步成了**：你读完这一页，能说出「这一阶段做完，用户能完整做成哪件事」和「哪些事这一阶段明确不做」。

再加一条：**刚才聊了那么多轮，有没有一条"当时另一个做法也行、被否掉了"的决定，只活在对话里？** 有就是漏了分流——对话下个 session 就没了。

### ★ 拍板 1：阶段目标 + 不做清单

**这是最贵的一个拍板点。** 方向错了后面全白做。

拍之前问自己两个问题：

1. 「不做」里的东西，真的可以先不要吗？
2. 阶段目标是不是一条**能跑通的链路**？说不出「用户从哪进来、做完什么、看到什么结果」，那它还是一批功能。

> **没有 approved 字段可以拍。** 拍板就是你读完点头，然后往下走。这套流程里没有任何机制读简报的 frontmatter，放个 bool 只会造出一个永远对不上的假状态。

### 步骤 2 · 必要时做一次探索（可选）

只在**技术上不确定能不能做**的时候做：外部接口给不给这个数据、这个量级扛不扛得住、这个格式解析得出来吗。

**我敲什么**：

```
先别建 task。我要验证 <一件具体的事>。
写个最小的东西验证它，不要进 src/，验完就删。
```

**三条纪律**：

1. **不建 task**——它不是一次交付，是一次问答
2. **不进 `src/`**，验完就删
3. **结论回写简报 §6 约束**，别只留在对话里

**说不出「我要验证什么，什么结果算通过」就别做这一步**——那不是探索，是提前开写。

### 步骤 3 · 切出第一片

**我敲什么**：

```
按 brief 的阶段目标排一下切片顺序，写进 §4。
要求：每一片都能独立端到端跑通，能验证一条真实的用户价值。
然后告诉我第一片是哪个。
```

**AI 会产出什么**：简报 §4 的切片清单表（切片 / 归属能力 / 依赖 / 端到端能验证什么）。

**怎么确认这步成了**——挨个问每一片：

> **做完这一片，有没有一件事是用户能真正做成的？**

- 有 → 是切片
- 没有 → 不是。「先把所有表建了」「先搭好框架」验证不了任何东西,它们该被**拆进**各自的片里,不单独成片

**Trellis 不会替你排顺序。** 它的原话是 *"Parent/child structure is not a dependency system"*——父子任务树不是依赖系统。谁先谁后必须写进简报 §4。

### ★ 拍板 2：第一片是哪个

选择的判据不是「哪个最重要」，是**哪个最能便宜地证伪你的假设**。

第一片会定下一批后面所有片都要沿用的结构（列表长什么样、异常怎么表达）。它值得多想一轮。

### 步骤 4 · 进 Trellis

**我敲什么**：

```
按 brief §4 的第一片建 task。
```

之后是 Trellis 自己的流程，本手册不复述。只说两处**你要停下来看**的地方：

```
Phase 1 Plan
  ├─ trellis-brainstorm 一问一答 → prd.md
  ├─ 有交互面 → 「用 lofi-prototype 出这一片的方案」
  │              ★ 拍板 3：选案
  └─ planning summary  ★ 拍板 4：你显式批准，它才能 task.py start

Phase 2 Execute   实现 → check
Phase 3 Finish    update-spec → commit → 归档
```

**关于 brainstorm 一问一答**：它被合同要求必须问（「Ask only one question per message」），而且**没有你的显式批准就不许开工**。这是好事——它是这条链上唯一真正的硬门禁。

**它问的每一个问题，都是简报里缺的一条。** 答的时候顺手补进简报，别只在对话里答——对话下个 session 就没了。

中断后接着干：`/trellis:continue`。

### ★ 拍板 3：选案（有交互面时）

**只画这一片。** 2–3 个方案，每个覆盖**这一片**的全部屏和状态，不覆盖后面几片。

**一次定。** 落选方案里想保留的要素当场说出来合并进定稿，**不留"再看看"**。

> 这一步是整条流程唯一真会失控的地方——不是画得多，是在方案之间反复摇摆。

走查时**主动去切异常态**。人的本能是只走主链路，但异常态是最贵的一类：文档里一句话，实现时三天。

### 步骤 5 · 下一片

第一片 Finish 之后，回到步骤 3：看简报 §4，选下一片，再进 Trellis。

**每 3–5 片，或阶段目标达成时**，走一次 [`04-checkpoint.md`](04-checkpoint.md)。逐片推进的代价就是没人看全貌，检查点是唯一的补救。

## 我该在哪停下来看

| # | 拍什么 | 在哪 | 拍错的代价 |
|---|---|---|---|
| 1 | **阶段目标 + 不做清单** | 简报 §2 §3 | 最贵，全白做 |
| 2 | **第一片是哪个** | 简报 §4 | 中等。它定下后面都要沿用的结构 |
| 3 | **选哪个方案** | 原型走查 | 原型上改是几分钟，实现后是几小时 |
| 4 | **planning summary** | Trellis，`task.py start` 之前 | 最后一道免费的闸 |
| 5 | **Phase 3 改了哪几条 spec** | Trellis Finish | AI 倾向于把一次性决定写成永久约定 |

**1 和 2 是真正值钱的两个。** 3、4、5 拍错了还能改。

## 常见卡点

### 「brainstorm 一直问我问题」

**这是设计如此，不是走样。** Trellis 的 brainstorm 被合同要求「每条消息只问一个问题」，直到没有用户该拍的决策为止。

两套提问纪律在这里会打架：Trellis 一次一问、`grilling` 一轮问完 frontier。**取 Trellis 的**——它在 planning 阶段是强制的，另一套只会跟它对着来。

**正确用法**：把它当简报的体检。它问的每一个问题都是简报里缺的一条——**答完顺手补进简报**。补完之后下一片的 brainstorm 会明显变短，因为它的 Evidence Rule 要求「能从仓库文档查到的就别问用户」。

**⚠️ 这条是推测，实跑后修正。** 如果补了简报它还是照问不误，那说明这个赌注错了，当场把结论写在这里。

### 「原型画出来我觉得都不对」

先分清是哪一层不对：

- **这一片的结构不对** → 回 `prd.md` 重新收敛这一片要做什么，再出方案
- **这一片就不该这么切**（比如它根本没法独立跑通）→ 回简报 §4 重排切片

两种都算一次**成功**的走查——它在 `task.py start` 之前拦住了错误。

### 「走查时发现这一片还需要别的屏」

判断多出来的是**本片必需**还是**顺手想加的**：

- 本片必需（少了它主链路就断了）→ 补进 `prd.md`，本片画
- 顺手想加 → 记进简报 §4 当后面的片

**切片不能在原型里静默长大。** 这是逐片模式最主要的失控形态：每片都"顺手多做一点"，三片之后就回到了一次做全。

### 「第三片的列表页跟第一片长得不一样」

逐片推进唯一真实的代价。防的办法只有一条：**出方案前先读 `docs/discovery/wireframe/*/final/` 下所有已定稿的屏**，同类屏沿用既有模式，偏离要说明理由。

这条写在 `lofi-prototype` 里，但你也要知道——因为发现不一致的通常是你，不是 AI。

### 「Trellis 一直问要不要建 task，很烦」

它在没有活跃 task 时每轮都问。简报没写完之前答**否**——Trellis 自己就允许这样，它的原话是用户说不就 *"skip Trellis for this session"*。`no_task` 是设计内的合法状态，不是你在绕过什么。

**要它这一轮彻底闭嘴**：消息里带上 `no-trellis` 这个词（独立成词，`no-trellisfoo` 不算）。那一轮的提示完全不注入。

```
no-trellis 我们先把简报第 3 节聊完
```

这是 Trellis 自带的逃生舱（开关在 `.trellis/config.yaml` 的 `prompt_injection.skip_keyword`，默认就是 `no-trellis`），**已实测**：带这个词跑，注入内容为空。

它和 [`00-setup.md`](00-setup.md) 步骤 5 那段粘贴**不是一回事，别互相替代**：粘贴是给 `no_task` 状态**加**一段「先看简报」的提醒（长期生效），`no-trellis` 是**关掉**当轮全部提醒（一次性）。写简报那几轮嫌吵就用后者，平时靠前者。

### 「我不想写简报，能直接建 task 吗」

能，简报是可选的，不存在时完全不阻塞。

**判据**：你说得出「第一片做什么、做完能验证什么」吗？说得出就直接建 task。说不出——那正是简报要帮你收敛的东西。

### 「grill 问了十几轮，一页纸根本装不下」

**装不下是对的，别把简报撑大。** 十几轮问出来的东西里，只有一类该进简报（需求边界），另外两类一类丢掉、一类进决策记录——见步骤 1 的「收尾：把问出来的东西分三类」。

判断简报是不是被撑坏了，看两个信号：

- 出现了「为什么这么定」的段落 → 那是决策记录的内容
- 出现了具体字段、接口、屏清单 → 那是 task `prd.md` 的内容

两个都没有、还是超过一页 → **这才是范围太大**，回 §3 砍「明确不做」。

### 「简报写完之后又想改」

改就是了，没有审批要作废。

简报**不是消耗品**：Trellis 里没有任何一处持有产品全貌，删了它这一层就归零。它跟着阶段目标一起更新，长期留着。

## 对 AI 说什么 · 速查

> ⚠️ **本节等实跑后填。** 下面是**待验证的初稿**，第一次跑的时候把你实际敲的、有效的那句替换进来。
>
> 没跑过就编 prompt，正是这套框架要防的事。

| 步骤 | 待验证初稿 | 状态 |
|---|---|---|
| 1 · 写简报 | `我想做 <一段话>。用 playbook/assets/brief-template.md 的结构落成 docs/discovery/brief.md。能自己查的先查了，剩下需要我拍板的一次列出来，每题给推荐答案` | 待验证 |
| 1 · 检查阶段目标 | `§2 的阶段目标是一条端到端链路还是一批功能？如果是后者，改成前者` | 待验证 |
| 1 · 结论分流 | `刚才问出来的按三类分：环境事实（丢掉）/ 需求边界（进 brief 哪一节）/ 有取舍的决定（进 decisions.md）。第三类按 decisions-template.md 的三条判据筛，缺一条就不写，并告诉我它缺哪条` | 待验证 |
| 1 · 让它闭嘴一轮 | `no-trellis <你要说的话>` | **机制已实测**（注入为空）；实际手感待验证 |
| 2 · 探索 | `先别建 task。我要验证 <一件具体的事>，写个最小的东西验证，不要进 src/，验完就删` | 待验证 |
| 3 · 排切片 | `按阶段目标排切片顺序写进 §4。每一片都要能独立端到端跑通。然后告诉我第一片是哪个` | 待验证 |
| 3 · 验切片 | `逐片回答：做完这一片，有没有一件事是用户能真正做成的？答不上来的说明不是切片` | 待验证 |
| 4 · 建 task | `按 brief §4 的第一片建 task` | 待验证 |
| 4 · 出原型 | `用 lofi-prototype 出这一片的方案` | 待验证 |
| 4 · 走查引导 | `切到「无权限」状态，审计员进来看到这个对吗？` | 待验证 |
| 4 · 补简报 | `刚才 brainstorm 问的那几个问题，把答案补进 brief 对应的节` | 待验证 |

**实跑后要记的**：哪一句需要重说才被正确理解、哪一步 AI 跑偏了要拉回来。那些才是这一节的价值。
