# 1 · 需求收敛

> 从一句话想法到一份收敛到**字段级**的完整 PRD。四步：讨论 → 写 PRD → 抛原型验字段 → 反写。
>
> 前三步都是为第四步服务的。**没有反写，前面三步等于没做**。

## 步骤

### 步骤 1 · 需求讨论

```
/grill-with-docs

我想做 <一段话，不用组织>。
先把你能自己查的查了，剩下真需要我拍板的一次列出来，每题给个推荐答案。
```

> 未实跑。

它会用 frontier 机制组织问题：前置已定的一轮问完，依赖未决的排到下一轮。**环境事实它该自己查，不该问你。**

#### 收尾：把问出来的东西分三类

**这一步必须显式做，别指望它自动发生。** grilling 的停止条件是 frontier 空，无界的，一轮一轮问下去很正常。问出来的东西会远多于任何一份文档能装的，而装不下不是文档太小，是它们本来就不该都进同一处：

| 问出来的 | 落哪 | 为什么 |
|---|---|---|
| **环境事实**：现有仓库有什么、某个库支不支持、这个格式解析得出来吗 | **哪也不落** | 它是 AI 该自己查的，查完用掉即可。存下来只会过期 |
| **术语**：这个东西在本项目里叫什么 | `CONTEXT.md` | 唯一宿主，由 `domain-modeling` 维护 |
| **需求边界**：做什么、不做什么、给谁用、什么时候算做完 | 完整 PRD | 这是 PRD 的正题 |
| **有取舍的决定**：当时另一个选项也能走通，被否掉了 | `docs/adr/` | 唯一宿主。PRD 答「做什么」，ADR 答「为什么是这样」 |

分不清一条属于哪类时问：**它是事实、术语、范围，还是选择？** 只有选择进 ADR。

ADR 的准入卡三条判据，权威源在 `~/.claude/skills/domain-modeling/SKILL.md`，**三条全中才写**。本仓不再转抄，因为转抄出来的第二份会先过期。

```
刚才问出来的，按四类分：环境事实（丢掉）/ 术语（进 CONTEXT.md）/
需求边界（进 PRD 哪一节）/ 有取舍的决定（进 docs/adr/）。
第四类按 domain-modeling 的三条判据筛，缺一条就不写，并告诉我它缺哪条。
```

> 未实跑。最后一句是防它把什么都判成「有取舍」。让它说出缺哪条判据，比让它自己把关有效。

### 步骤 2 · 写完整 PRD

用 `create-prd-skill`，产物落 `docs/discovery/prd.md`。

它按 L1–L4 分级裁剪深度，所以**先让它判级**：小需求被判成 L4 会产出十几章没人读的东西，大需求被判成 L1 则漏掉该拍的板。

**怎么确认这步成了**：你读完能说出「这一阶段做完，用户能完整做成哪件事」和「哪些事这一阶段明确不做」。

再加一条：刚才聊了那么多轮，有没有一条「当时另一个做法也行、被否掉了」的决定，只活在对话里？ 有就是漏了分流。

### ★ 拍板 1：范围 + 明确不做

**这是最贵的一个拍板点。** 方向错了后面全白做。

拍之前问自己两个问题：

1. 「不做」里的东西，真的可以先不要吗？
2. 范围是不是一条**能跑通的链路**？说不出「用户从哪进来、做完什么、看到什么结果」，那它还是一批功能。

> **没有 approved 字段可以拍。** 拍板就是你读完点头，然后往下走。

### 步骤 3 · 抛原型验字段

**只在纸上推不动的时候做**：状态机在某几种输入下会变成什么、这几个字段够不够表达这件事、这个异常态该长什么样。

```
先别建 task。我要验证 <一件具体的事>。
用 prototype 的 LOGIC 分支写个最小的东西验证它，不要进 src/，验完就删。
```

> 未实跑。

**三条纪律**：

1. **不建 task**，它不是一次交付，是一次问答
2. **不进 `src/`**，验完就删
3. **走 LOGIC 分支**。`prototype` 第一步是 "Pick a branch"，没有任何机制挡得住它选 UI 分支，而 UI 分支会在真项目路由里开几个变体，跟下一篇的全量高保真是两条路。发现它跑偏就当场拉回来

说不出「我要验证什么、什么结果算通过」就别做这一步，那不是探索，是提前开写。

### 步骤 4 · 反写 PRD

把原型暴露出来的字段、状态和边界情况**编进 PRD 正文**。

**写成 delta，不要追加。** ADDED / MODIFIED / REMOVED 三个标记直接改正文，格式和理由在 `.trellis/spec/guides/source-of-truth.md`（编辑 `docs/discovery/**` 时会自动注入）。

**这一步只做一次，在阶段边界上。** 每验一次就改一次 PRD，它会变成对话转储，那时候想知道现状就得从头读。

**怎么确认这步成了**：PRD 里每一个 UI 上会出现的字段，你都能说出它的取值范围和空值时的表现。说不出的那几个，就是高保真会开始猜的地方。

## 我该在哪停下来看

| # | 看什么 | 漏了会怎样 |
|---|---|---|
| 1 | 范围 + 明确不做（★ 拍板 1） | 最贵。方向错了后面全白做 |
| 2 | 有取舍的决定进了 `docs/adr/` 没有 | 对话下个 session 就没了，半年后自己推翻自己 |
| 3 | **字段级收敛到了没有** | 下一篇的高保真会替你猜，而且猜完就被当成已定 |

第 3 条是这一篇存在的理由。前两条漏了会疼，第 3 条漏了**不会疼**。它会在十几片之后以「结构不对」的形式出现。

## 常见卡点

### 「brainstorm 一直问我问题」

设计如此。见[场景首页](README.md)「五件反复出现的事」第四条。

### 「grill 问了十几轮，PRD 装不下」

装不下是对的。十几轮问出来的东西分四类，只有一类该进 PRD，见步骤 1 的收尾。

判断 PRD 是不是被撑坏了，看两个信号：

- 出现了「为什么这么定」的段落 → 那是 ADR 的内容
- 出现了具体的屏和交互序列 → 那是高保真的内容

两个都没有、还是太长 → **这才是范围太大**，回去砍「明确不做」。

### 「PRD 写完之后又想改」

改就是了，没有审批要作废。

PRD **不是消耗品**：Trellis 里没有任何一处持有产品全貌，删了它这一层就归零。它跟着阶段目标一起更新，长期留着。

### 「Trellis 一直问要不要建 task」

这几轮里嫌吵就用 `no-trellis`，见 [`../setup/04-workflow-prompts.md`](../setup/04-workflow-prompts.md) 的常见卡点。
