# 3 · 切片

> 把定稿之后的东西切成能一片一片交付的顺序，写进 `docs/discovery/slices.md`。
>
> 这是进 Trellis 之前的最后一步。

## 开始之前

- [ ] 完整 PRD 已收敛到字段级
- [ ] 有交互面的话，高保真已定稿。**没定稿就来切，第四列会是空的**，而空的第四列等于让实现期的子 agent 自由发挥

## 步骤

### 步骤 1 · 打 `/vertical-slicing`

```
/vertical-slicing
```

> 未实跑。

这一步不能省，也不能只把模板路径指给 AI。 只指模板的话，切片判据、尺度锚和阻塞边规则一条都不会加载。AI 会照着模板的表格填，但填出来的东西没经过任何判据。

它产出 `docs/discovery/slices.md`，三节：当前阶段目标 · 切片清单 · frontier。

### 步骤 2 · 逐片验四列

切片清单每片四列，**填不满的多半不是一片**：

| 列 | 内容 | 填不出来说明 |
|---|---|---|
| 切片 | 一个短标题 | —— |
| 阻塞边 | 哪几片必须先完成 | —— |
| 端到端能验证什么 | 一句话，用户视角 | **它不是切片** |
| 本片对应的高保真屏 | `design-system/screens/` 下的具体路径 | 定稿没覆盖到，或者这一片切错了 |

三条你当场就能用的判据：

1. 说不出「做完这一片，有一件事是用户能真正做成的」 → 不是切片。「先把所有表建了」「先搭好框架」验证不了任何东西，该被拆进各自的片里
2. **标题里出现「和」「与」** → 那是两个任务，拆开
3. 一个全新 context window 装不下 → 太大。实现发生在子 agent 的全新 context 里，那个窗口就是天然的尺寸上限

**阻塞边只写真的挡住它的。** 顺序不是依赖。把「碰巧排在前面」写进阻塞边，会让每一片看起来都是串行的，而其中有些本来随时可以开工。

### 步骤 3 · 检查第四列

**这一列不是装饰。** 它是进 task 时填 `implement.jsonl` 的取值范围。

空着的格子只有两种解释：定稿没覆盖到这一片（回 [`02-hifi.md`](02-hifi.md) 补），或者这一片切错了（重切）。

### ★ 拍板 3：切法 + 第一片是哪个

**一次定。** 落选切法里想保留的当场合并进定稿的那一版。最多两轮，第二轮之后仍有分歧的记成「待确认」，不开第三轮。

第一片的判据不是「哪个最重要」，是**哪个最能便宜地证伪你的假设**。它会定下一批后面所有片都要沿用的结构：列表长什么样、异常怎么表达。值得多想一轮。

## 常见卡点

### 「有一片映射到了十几屏」

skill 会说一次「这一片可能切太大了」，**但不会拦你**。有些片就是大，判断是你的。

判据还是那条：一个全新 context window 装不装得下。装不下就拆。

### 「这次要做的是宽重构」

**不进这张表。** 改一个共享符号的类型、重命名一个到处都在用的字段，影响面铺满全仓，硬塞进纵向切片会让每一片都是红的。

走 expand–contract，见 [`06-off-path.md`](06-off-path.md)。

### 「已经有 `slices.md` 了，这次只是加一片」

只做增量，别重排整张表。见 [`06-off-path.md`](06-off-path.md)。

### 「frontier 怎么算」

frontier 是**阻塞边已全部完成**的片，也就是现在就可以开工的。

**要算，不要从上往下数。** 从表头顺着数会漏掉那些其实早就能开工的片，那正是这一节存在的理由。每片做完更新一次。

### 「切片清单和 PRD 对不上」

以 PRD 为准，回去改 PRD 或改定稿，**别在切片清单里补需求**。

切片这一步只回答「多大、谁挡谁、对应哪几屏」。往切片清单里写一条缺失的需求，是在换个名字定需求。
